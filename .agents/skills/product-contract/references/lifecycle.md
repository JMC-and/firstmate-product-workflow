# Existing lifecycle integration

[Product Plan](../../product-plan/SKILL.md) stops at approved artifact emission; [Product Build](../../product-build/SKILL.md) owns explicit later execution through the existing build interface.
The shared executable validator/evaluator owns all contract admission and acceptance predicates.
Shell adapters only invoke it; they do not reinterpret contract data.
New ship dispatch in every delivery mode requires an approved assignment before endpoint/work-copy allocation and is checked again before launch.
Terminal launches revalidate when the shell actually executes; the thread-only path validates immediately before submitting its first turn.
Batch dispatch inherits the same per-item path.
Scouts and second mate charters remain preparatory or supervisory, not product implementation.

Scout promotion requires an approved assignment before publishing instructions and repeats the check before publication.
Controlled relaunch checks before stopping the old worker and again through the ordinary spawn path.
Generated ship instructions require the same check before product edits and after interruption or changed requirements.
This is shared logic across all supported harnesses and runtime backends, not vendor-output detection.
There is no claim that local tooling can prevent a malicious same-user process or an already running agent from ignoring instructions.

The existing shared done evaluator validates assigned acceptance before accepting an actual ready claim, including forge shortcuts.
A no-mistakes implementation handoff remains a handoff and does not prematurely require final evidence.
Both PR and local landing recheck the exact candidate against the same acceptance evaluator.
Existing delivery modes, pipeline custody, merge permission, isolated work copies, landed-work checks and cleanup remain authoritative.

Already recorded tasks without a generated required marker and without a binding remain legacy for restart/cleanup compatibility.
They receive no product-acceptance certificate and no retroactive new requirement.
Every new ship and every promotion is required regardless of marker presence.
An existing task with a binding cannot fall back to legacy when that binding is stale or invalid.

Contracts and product evidence live separately from disposable worker records.
Cleanup of a landed slice does not certify or close its parent product.
A backlog work-item completion is a delivery bookkeeping event, not product acceptance.
Use the product evaluator for any parent-product completion claim even after every slice is closed.
Retain private contract history beyond normal worker cleanup and apply the owner's explicit retention policy rather than deleting originals as routine cleanup.

Each second mate records its own scoped contracts and work in its owning home.
Route exact parent approval and assignments through the established parent channel; do not reconstruct another home's child tree or treat a missing local original as permission to proceed.
A worker without write access to the private contract store reports proof in its authorized task directory for its firstmate to record.
