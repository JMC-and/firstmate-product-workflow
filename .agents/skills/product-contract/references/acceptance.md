# Independent acceptance

Before approval, a planning context other than the specification author reads the complete original sources first.
It reconstructs obligations before reading the proposed mapping.
Audit every source and atomic clause for omissions, weakening, negation loss, generalized exceptions, contradictions, invented behavior and unresolved decisions.
Report exact IDs and original quotes for every finding.
The report binds to the exact contract hash, enumerates inspected source and clause IDs, and records all seven checks.
An incomplete report, any finding, stale hash or self-audit stops approval.
Regeneration invalidates the prior audit and requires a fresh independent pass.

During implementation, product acceptance belongs inside the existing selected validation path.
Give that path the approved source obligations, exact candidate, environment, oracle, journey and evidence instructions before its implementer summary.
Use the pipeline's acceptance runner in no-mistakes mode, not another serial code review or parallel fixer.
Faster paths use their authorized acceptance mechanism without inventing an extra manual clean-verdict requirement.
A separate worker/reviewer is authorized only under the existing explicit-deliverable rules.

Acceptance observations must be independently attributable rather than silently inferred from implementation claims.
A failure revealing a product choice, security-sensitive operation or enlarged budget follows existing ask-user authority.
Fixes preserve the approved scope and current pipeline custody.
Retest failed and impacted paths at the final candidate; the current evaluator intentionally provides no stale-head carry-forward shortcut.
